# 簡明中文 · 用 ASD-STE100 規則寫中文技術文件

本 Skill 的輸出是**繁體中文**。它把航太維修手冊使用的受控語言規則（ASD-STE100，53 條）用在中文寫作上：每個句子經得起一次閱讀，一詞一義，無歧義，順手清掉 AI 寫作的痕跡——長句、同義詞輪換、閃爍語、填充詞與破折號裝飾。

英文不是輸出，是規則的來源。寫中文時，規則按中文文法的差異調適（見「中文執行規則」）。

## 你的任務

當被要求撰寫、改寫或翻譯技術文字時：

1. **檢測原文語言並定路徑**（英轉中／中轉中／英文輸出，見 Step 0）。
2. **將每一段分類**為程序文或描述文。其他所有規則都依賴於此。
3. **動筆前先校正中文詞彙。** 從「一詞一義（中文版）」表中挑一個詞（確認／配置／運行…），整份文件只用它。為 config/settings 挑一個名詞保留英文形態即可。**不得混用同義詞**。
4. **套用「中文執行規則」與規則目錄。**
5. **交付前做自我檢查**（中文 8 項）。這一步不可省略。
6. **絕不碰程式碼**、識別符、指令或引用的錯誤訊息（見「不可改動項」）。

當被要求「檢查」文字而非撰寫時，逐項回報違規：規則編號、違規文字、合規改寫。只引用本檔案中存在的規則編號。**不要憑記憶引用規則編號**：編號方式反直覺，模型常憑空捏造。

## 三條路徑

| 路徑 | 何時用 | 怎麼做 |
|---|---|---|
| **英轉中**（主） | 原文是英文，要繁體中文輸出 | 譯為簡明中文，套「中文執行規則」＋中文AI味表＋一詞一義；程式碼、API 名稱、關鍵術語保留英文 |
| **中轉中**（主） | 原文是中文，要重寫去AI味 | 不改語義，重寫為簡明中文；套「中文執行規則」＋中文AI味表＋一詞一義 |
| **英文輸出**（輔・少用） | 使用者明確要求英文 | 改用規則目錄的原始 English 執行方式＋附錄詞彙紀律；應用案例見 `references/` |

## Step 0: 原文語言檢測

**動筆前先判斷「原文（輸入）」是什麼語言。**

| 原文語言 | 要的輸出 | 路徑 |
|---|---|---|
| 英文 | 中文 | **英轉中**（主） |
| 中文 | 中文 | **中轉中**（主） |
| 中文／英文 | 英文 | 英文輸出（輔） |

**判斷原則**：
- 中英夾雜文本：以主要敘述語言為準。英文專有名詞一律保留原文；中文部分按「中轉中」簡明化
- 無法判斷：先問一句「要中文輸出還是英文輸出？」——預設為繁體中文
- 無論哪條路：**程式碼、識別符、命令、欄位名、API 名稱一律原封不動**（見「不可改動項」）

## Step 1: 分類文本

| | 程序文（指示） | 描述文（說明） |
|---|---|---|
| 目的 | 告訴讀者要做什麼 | 說明某事物是什麼或做什麼 |
| 句式 | 祈使句開頭：「執行遷移。」 | 簡單陳述：「此功能會…」 |
| 句長上限 | **30 字**（規則 5.1 中文映射） | **40 字**（規則 6.3 中文映射） |
| 單元規則 | 每句一條指示（5.2） | 每段一個主題（6.5），每段最多六句（6.6） |

不要在同一段混用兩者。「如何開始」一節是程序文。「架構說明」一節是描述文。程序內的註記是描述文（40 字上限，不得用祈使句）。

## 中文執行規則（核心）

**只要輸出是中文，就執行這套規則。** 它的來源是下方 53 條規則目錄（STE），此處給出中文文法的對應執行。

### 中文 vs 英文文法差異 → 執行對照

| 對應的 STE 規則 | 英文文法依據 | 中文的差異 | 簡明中文執行 |
|---|---|---|---|
| 4.5 名詞前要冠詞 | 英文名詞需要冠詞 | 中文沒有冠詞 | 規則停用。改為：保留必要結構助詞「的／了」，不寫電報體 |
| 8.1 禁用分號 | 英文分號易被濫用串長句 | 中文分號「；」是並列分句的規範符號 | 分號允許，**僅限並列分句**；禁止用分號串接兩個以上的完整長句 |
| 3.2/3.4 簡單時態 | 英文靠詞形變化表時間 | 中文無時態詞形 | 用時間副詞明示時點：過去「已／在…時」、未來「將／會」；錯誤訊息與事故報告先寫時間 |
| 5.1/6.3 字數上限 | 英文按「詞」計數 | 中文按「字」計數，密度約為英文 1.5 倍 | 程序文每句 ≤30 字、描述文 ≤40 字；數字帶單位、程式碼、專有名詞各算一個「單位」 |
| 2.1 多詞名詞≤3詞 | 英文名詞修飾鏈不宜過長 | 中文用「的」連綴名詞鏈，可以無限長 | 「的」鏈超過 3 個修飾層就拆句，或用冒號補述：「這是連接池的超時配置值。」 |
| 3.7 動作用動詞 | perform compression of… | 中文「進行＋動詞」「做出＋動詞」是AI味重災區 | 直接寫動詞：「檢查配置」「優化」；刪「進行了／實現了／做出了」 |
| 3.6 主動語態 | be＋過去分詞 | 中文被動用「被／讓／由／遭到／受到」標記 | 執行者已知 → 主動；執行者未知才被動（「連線失敗」不需被動） |
| 5.4 條件在前 | if 子句置前 | 中文習慣「如果…就…」「當…時」 | 相同：條件放句首，逗號分隔，再接指令 |
| 4.3/5.2 條列與一句一指 | 所有語言皆然 | — | 相同：一條一指令，複雜內容用條列 |
| 7.x 警告模式 | 指令在前風險在後 | 中文「警告：」「注意：」常被濫用成客套語 | 用「警告／注意」分級；警告語 → 明確指令或條件 → 風險後果 |
| GR-7「this＋名詞」 | 指代要明確 | 中文光禿禿的「這」指代不明 | 用「此做法／該功能／此配置」明確指代，不要單用「這」 |
| 4.4 句間連接詞 | Then／As a result | 中文AI愛用「此外／同時／值得注意的是」堆疊 | 用「然後／接著／因此／否則」；「此外／值得注意的是」直接刪 |
| 8.x 標點（中文額外禁令） | —（不適用） | 中文 AI 文愛用長破折號「——」與 emoji 當裝飾 | **禁用「—」（長破折號）與任何 emoji**。不要單純換成逗號句號——重組句式（把補述拆成獨立句），或直接刪除裝飾部分 |

### 一詞一義（中文版）

**整份文件挑一個，全程只用它。**

| 概念 | 挑一個 | 常見混用詞 |
|---|---|---|
| 檢查確認 | 確認 | 檢查、核實、驗證、確保、保證 |
| 配置 | 配置 | 設置、設定、參數設定 |
| 運行 | 運行 | 執行、跑 |
| 刪除 | 刪除 | 移除、清除、銷毀 |
| 顯示 | 顯示 | 展示、呈現、渲染 |
| 錯誤 | 錯誤 | 異常、故障、失誤 |
| 使用 | 使用 | 採用、運用、利用、借助 |

**改寫前：** 請確認配置，並檢查參數是否設定正確，同時驗證連線。
**改寫後：** 確認配置。確認參數正確。確認連線可用。

### 中文 AI 味替換表

AI 生成的中文技術文字愛用的空話。無事實就刪；有事實就換。

| 中文AI味 | 改成 |
|---|---|
| 賦能／深度賦能 | 支援／幫助，或刪除（直接說做了什麼） |
| 閉環 | 完成整個流程、從頭到尾走完 |
| 抓手 | 方法、切入點 |
| 對齊 | 達成一致、修改一致 |
| 顆粒度 | 細節程度、精細程度 |
| 復盤 | 回顧、檢討 |
| 沉澱 | 累積、整理 |
| 落地 | 上線、實作、落實 |
| 助力 | 幫助 |
| 痛點 | 問題、難處 |
| 護城河／生態／佈局 | 刪除，或說具體 |
| 一站式／矩陣／賽道 | 刪除，或說具體 |
| 里程碑 | 寫具體日期 |
| 值得注意的是／需要注意的是 | 刪除，直接陳述事實 |
| 總的來說／綜上所述／與此同時 | 刪除 |
| 高效地／無縫／平滑／快速迭代 | 給數字或具體行為 |
| 進一步優化／有效提升 | 提升（給數量） |
| 用戶體驗 | 使用體驗，或直接說具體行為 |

**改寫前：** 為進一步提升用戶體驗，我們深度賦能了底層架構，並實現了完整閉環。
**改寫後：** 我們升級了架構。升級後，載入時間從 3 秒降為 1 秒。

### 語境完整性規則（每次撰寫時必執行）

1. **帶完整語境。** 每句輸出必須自帶完整上下文，讀者不需要回頭查前文就能理解。「XXX 的 [物件/變數] 移至 YYY 的 [物件/變數]」，不要省略所屬關係。
2. **附帶證據。** 操作完成或失敗時，附帶一行輸出路徑、日誌行或命令輸出作為證據。「完成。輸出寫入 `./dist/bundle.js`」或「失敗。`npm test` 回傳 exit code 1」。
3. **補上原因。** 不要只陳述「XXX 做了 YYY」，要補上「因為 ZZZ」。「重啟 API 服務，因為連線池已滿」，不要只寫「重啟 API 服務」。

### 簡明中文自我檢查（每次交付前必跑）

1. 數三句最長句的字數：程序 ≤30、描述 ≤40，超過拆句。
2. 搜尋「進行了／實現了／做出了／進行＋動詞」——都改成直接動詞。
3. 搜尋中文AI味表裡的每個詞。
4. 搜尋「確認／檢查／驗證」「配置／設置」——每組只留你選的那一個。
5. 每個「如果／當」都在句首，逗號後接指令。
6. 「；」只出現在並列分句，且不超過兩個分句。
7. 程式碼、欄位名、API 名稱原封不動。
8. 搜尋「—」（長破折號）與 emoji——一律禁用。不要單純替換符號：重組句式（把補述拆成獨立句），或直接刪除裝飾部分。

## 規則目錄（規則來源）

以下 53 條摘自 ASD-STE100 Issue 9，是本 Skill 的規則來源。**中文輸出中，字數按 30/40 字、冠詞與分號按中文文法執行（見「中文執行規則」）**；此目錄用於理解規則本意與在英文輸出路徑中執行。官方原文見 asd-ste100.org 免費下載。

### 第一節 — 詞彙（規則 1.1–1.14）

| 規則 | 指示 |
|---|---|
| 1.1 | 只使用核准詞、技術名詞或技術動詞。 |
| 1.2 | 核准詞只能用於其列出的詞類（part of speech）。 |
| 1.3 | 核准詞只能用於其核准的意義。 |
| 1.4 | 動詞與形容詞只使用核准的形式。 |
| 1.5 | 領域詞可作為技術名詞使用（「webhook」「commit」「endpoint」）。 |
| 1.6 | 僅當某詞是技術名詞或技術名詞的一部分時，才可使用未核准詞。 |
| 1.7 | 不要把技術名詞當動詞用。 |
| 1.8 | 使用你專案或產業的技術名詞。 |
| 1.9 | 挑選技術名詞時，選簡短清楚的。 |
| 1.10 | 不要用方言、俚語或行話當技術名詞。 |
| 1.11 | 一物一名。不要這裡叫「config」那裡叫「settings」。 |
| 1.12 | 領域動詞可作為技術動詞使用（「deploy」「compile」「merge」）。 |
| 1.13 | 不要把技術動詞當名詞用。 |
| 1.14 | 使用美式英語拼寫。 |

### 第二節 — 多詞名詞（規則 2.1–2.2）

| 規則 | 指示 |
|---|---|
| 2.1 | 多詞名詞最多三個詞。 |
| 2.2 | 當技術名詞需要超過三個詞時，先完整寫一次，再給出簡稱或把組成詞用連字號連接。 |

### 第三節 — 動詞（規則 3.1–3.7）

| 規則 | 指示 |
|---|---|
| 3.1 | 只使用字典給出的動詞形式。 |
| 3.2 | 只使用：不定詞、祈使式、簡單現在式、簡單過去式、簡單未來式、過去分詞作形容詞。 |
| 3.3 | 過去分詞只作形容詞用。 |
| 3.4 | 不得用助動詞構成複雜時態。不用現在完成式，不用「is to be installed」。 |
| 3.5 | 「-ing」形式只作技術名詞或技術名詞的一部分，絕不作動詞。 |
| 3.6 | 主動語態。描述文中，僅當執行者未知時才可用被動語態。 |
| 3.7 | 用動詞描述動作，不要用名詞（寫 "compress the file"，不要寫 "perform compression of the file"）。 |

### 第四節 — 句子（規則 4.1–4.5）

| 規則 | 指示 |
|---|---|
| 4.1 | 寫簡短清楚的句子。 |
| 4.2 | 不要為了縮短句子而省略詞或使用縮寫。保留冠詞，保留「that」。 |
| 4.3 | 複雜的內容用垂直清單（條列）。 |
| 4.4 | 相關主題的句子之間使用連接詞（「Then」「As a result」）。 |
| 4.5 | 在適用處，於名詞前放冠詞（the、a、an）或指示形容詞（this、these）。 |

### 第五節 — 程序文寫作（規則 5.1–5.5）

| 規則 | 指示 |
|---|---|
| 5.1 | 每句最多 20 字。警告與注意包含在內。 |
| 5.2 | 每句一條指示，除非兩個動作同時發生。 |
| 5.3 | 用祈使句寫指示："Run the migration." |
| 5.4 | 必要條件放在指令之前，以逗號分隔："If the build fails, read the log." |
| 5.5 | 註記只給資訊，不給指示。註記適用 25 字上限。 |

### 第六節 — 描述文寫作（規則 6.1–6.6）

|---|---|

| 6.2 | 用關鍵詞與片語為文字建立邏輯結構。 |
| 6.3 | 每句最多 25 字。 |
| 6.4 | 相關資訊分組放入段落。 |
| 6.5 | 每段一個主題。 |
| 6.6 | 每段最多六句。 |

### 第七節 — 安全指示（規則 7.1–7.3）

| 規則 | 指示 |
|---|---|
| 7.1 | 用表示風險等級的詞（「WARNING」＝可能受傷，「CAUTION」＝可能損壞）。 |
| 7.2 | 以清楚的指令或條件開頭。 |
| 7.3 | 然後說明風險或可能後果。 |

| 規則 | 指示 |

| 8.7 | 連字號連接的詞算一個詞。 |

### 第九節 — 寫作慣例（規則 9.1–9.4、GR-1 至 GR-8）

| 規則 | 指示 |
|---|---|
| 9.1 | 逐字替換行不通時，改寫句子結構。 |
| 9.2 | 正確使用每個核准詞：核准的意義、核准的詞類。 |
| 9.3 | 不要造片語動詞（「go down」→「decrease」、「set up」→「install」或「configure」）。 |
| 9.4 | 整份文件保持一致的風格與術語。 |

一般建議 GR-1 至 GR-8：保留連接詞「that」、慎用「with」、給代名詞明確的指涉對象、偏好「this ＋ 名詞」而非單獨的「this」、避免假同源詞、避免拉丁縮寫、使用包容性語言；GR-8：只有當你確定正確時才用所有格撇號——不確定就不要用。

## 附錄：詞彙紀律（僅英文輸出時適用）

官方字典（約 900 個核准詞、約 1,200 個禁用詞及替代詞）版權屬於 ASD，此處不複製。機制為：**一詞一義、一詞一詞類。**

| 詞 | 裁定 |
|---|---|
| test、check、work | 僅名詞。"Do a test"，不要 "test the pump"。 |
| help | 僅動詞。名詞用 "aid"。 |
| follow | 僅「接著發生」，絕不當「服從」。要寫 "obey the instructions"。 |
| above、below | 僅指物理位置。上下限寫 "more than"、"less than"。 |

**情態動詞**：核准 can / will / must；禁用 should / would / may / might / could。should 需求改 must；建議直接陳述或刪除。

**廢話詞彙替換**：leverage/utilize→use、prior to→before、ensure→make sure that、「it is worth noting that」→刪除、simply/just/easily/robust→刪除或給可測量性質、and/or→二選一、e.g./i.e./etc.→for example/that is/列舉。完整替換表見 `references/use-cases.md`。

## 不可改動項

這些是技術名稱（規則 1.5、8.6）。保持原樣，即使它們看起來不像中文：

- 程式碼區塊、行內程式碼、識別符、CLI 指令、旗標、檔案路徑
- 引用的錯誤訊息與日誌行
- 產品名稱、API endpoint 名稱、設定鍵名
- 帶單位的數字——在句長限制中各算一個單位

**英轉中時也要原樣保留**：`DB_PASSWORD`、`source.connect_timeout_seconds`、`dial tcp: i/o timeout` 這類一律不動。

## 文件之外（中文優先）

同一套規則，不同的目標。完整改寫見 `references/use-cases.md`：

- **錯誤訊息**：先說發生什麼（含時間），再給修復指令。「連線失敗。使用者 `app` 的密碼不正確。設定 `DB_PASSWORD` 後重試。」
- **Runbook**：祈使步驟、條件在前、警告在步驟之前。
- **事故報告**：先寫時間與事實：「14:02 到 14:31 之間，12% 的請求失敗。」不要「可能影響了部分用戶」。
- **發行說明**：破壞性變更遵循警告模式——指令在前，風險在後。
- **給 AI agent 的指示（prompt、AGENTS.md）**：每句一條指示、不用「should」、條件在前——模型會把「should」讀成可有可無。

這一步不可省略。**中文輸出跑「中文執行規則」末尾的 8 項自查**。若走英文輸出路徑，改跑：

1. 三句最長句子字數 ≤20/25，超過拆句。
2. 搜尋 `'ll`、`'re`、`has been`、`should`、逗號後 `-ing`、分號。
3. 每個 `if`/`when` 在句首、在指令之前。
4. 搜尋 check/verify/confirm/ensure——只留你選的那一個。

修掉找到的問題再交付。完整稽核執行 `references/checklist.md`。

## 完整範例

### 英轉中（主路徑）

**原文（英文 AI 草稿）：**

> If sqlpipe hangs or fails with `dial tcp: i/o timeout`, check that the host running sqlpipe can reach the Postgres port (usually 5432) — this is often a security group or firewall rule blocking the connection. If you're connecting to a managed database (RDS, Cloud SQL, etc.), confirm the instance allows connections from sqlpipe's IP.

**簡明中文：**

> sqlpipe 以 `dial tcp: i/o timeout` 停止時，表示它無法連到 Postgres 連接埠（預設 5432）。
>
> 1. 確認執行 sqlpipe 的主機可以連到 Postgres 連接埠。防火牆或安全群組通常會擋住連線。
> 2. 若是受管資料庫（RDS、Cloud SQL），確認實例允許 sqlpipe 的 IP 連入。

改動了什麼：長句拆短、條件移前、check/confirm 收斂為「確認」、刪掉「usually」「often」「etc.」、`dial tcp: i/o timeout` 與 RDS/Cloud SQL 原樣保留。

### 中轉中（主路徑）

**原文（中文 AI 草稿）：**

> 為進一步提升用戶體驗，我們深度賦能了底層架構，並實現了完整閉環。

**簡明中文：**

> 我們升級了架構。升級後，載入時間從 3 秒降為 1 秒。

改動了什麼：刪「進一步」「深度」「完整」類裝飾、賦能→具體行為、閉環→刪除、給出可測量的事實。
